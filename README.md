# 素材审核与发布排期 Agent

## 1. 项目简介

本项目是一个基于大语言模型（LLM）的素材审核与发布排期 Agent，面向内容运营场景，帮助内容团队完成素材信息检查、发布规则审核、可用时段查询和排期草稿管理。

Agent 根据用户的排期需求，调用不同工具获取素材信息、检查审核规则和查询可用发布时间，并结合当前排期情况动态决定下一步操作。

当用户指定的发布时间不可用时，Agent 可以重新决策并推荐其他可用时段，但不会擅自修改用户的硬性时间要求。对于替代时间，必须等待用户确认后才能保存排期草稿。

**本项目仅负责生成和保存排期草稿，不执行真实内容发布。**

## 2. 核心功能

- **素材信息读取**：根据素材 ID 获取素材信息，检查必要元数据是否完整。
- **审核规则检查**：根据素材状态和风险等级判断是否允许进入排期流程。
- **可用时段查询**：查询可用发布时间，并考虑已有排期草稿和占用时段。
- **动态排期决策**：根据用户要求、素材审核结果和时段可用情况，决定正常排期、推荐替代时间或阻断操作。
- **用户确认机制**：替代时间必须经过用户确认，确认后才保存草稿；用户取消则不保存。
- **草稿持久化**：将排期草稿保存为 JSON 文件，并支持查看已有草稿。
- **重复提交处理**：识别相同素材和发布时间的已有草稿，避免重复创建。
- **异常处理**：处理素材信息缺失、非法时间、时段冲突和草稿保存失败等情况。

## 5. Agent 工作流程

1. 接收用户的素材 ID 和发布时间要求。
2. 调用素材读取工具，检查素材是否存在以及必要元数据是否完整。
3. 调用审核规则工具，根据素材状态和风险等级判断是否允许排期。
4. 检查是否已经存在相同素材和发布时间的排期草稿。
5. 查询当前可用发布时间。
6. 将用户需求、审核结果和可用时段提供给大语言模型，由模型生成下一步决策。
7. Agent 对模型返回的决策进行解析和校验，避免采用不可用或不符合用户要求的时间。
8. 如果需要调整发布时间，向用户提出替代时间建议并等待确认。
9. 用户确认后调用草稿保存工具；用户取消则终止操作，不保存草稿。

### 决策边界

- 素材信息不完整：阻断排期。
- 高风险素材：阻断排期。
- 中风险素材：需要人工审核。
- 用户指定的硬性时间不可用：阻断排期，不自动更换时间。
- 用户允许调整或未明确要求必须使用指定时间时：可以提出替代时间建议，但需要用户确认。
- 用户取消：不保存草稿。
- 保存失败：明确返回失败状态，不报告保存成功。
- 重复提交：不重复创建相同素材和发布时间的草稿。

## 6. 环境配置与运行

### 6.1 安装 Python 依赖

建议在项目根目录创建并激活虚拟环境：

```bash
python -m venv .venv
```

Windows PowerShell：

```powershell
.venv\Scripts\Activate.ps1
```

安装依赖：

```bash
pip install -r requirements.txt
```

### 6.2 配置 Ollama

首先安装并启动 Ollama。

下载项目使用的模型：

```bash
ollama pull qwen3:1.7b
```

确认模型已经安装：

```bash
ollama list
```

项目通过 Ollama 本地 API 进行模型调用，默认配置为：

- API 地址：`http://localhost:11434/api/chat`
- 模型名称：`qwen3:1.7b`

相关配置位于 `src/llm.py`。

### 6.3 启动项目

在项目根目录运行：

```bash
python src/main.py
```

根据命令行提示输入排期需求。

示例：

```text
安排素材 M01 在 18:00 发布
```

查看已有草稿：

```text
查看草稿
```

退出程序：

```text
exit
```

或：

```text
quit
```

## 7. 测试

项目使用 Python 内置的 `unittest` 框架进行测试。

在项目根目录执行：

```bash
python -m unittest discover -s tests -v
```

当前测试覆盖三个主要模块：

- **Agent 测试**：正常排期、替代时间建议、用户取消、高风险素材、信息缺失、无效模型建议和保存失败等场景。
- **Tools 测试**：素材读取、审核规则、可用时段查询、重复保存和非法排期等场景。
- **Storage 测试**：草稿保存、读取、重复保存、非法时间和保存失败等场景。

当前已完成 **31 项单元测试，全部通过**。

## 8. 数据存储

排期草稿以 JSON 文件形式保存在：

```text
data/drafts/
```

文件名由素材 ID 和发布时间组成，例如：

```text
M01_1900.json
```

草稿中包含以下信息：

- `material_id`：素材 ID
- `publish_time`：发布时间
- `schedule_request`：用户的原始排期要求
- `review_status`：审核状态
- `schedule_status`：排期状态
- `draft_status`：草稿保存状态
- `created_at`：创建时间

程序重新启动后，已经保存的草稿仍然保留，可以通过“查看草稿”读取。

## 9. 项目限制

- 当前使用本地 Qwen3:1.7b 模型进行决策，模型输出仍需要通过 Python 代码进行校验。
- 当前素材数据和部分占用时段使用项目内置的模拟数据。
- 草稿保存在本地 JSON 文件中，没有接入外部数据库或内容管理平台。
- 用户确认后仅保存排期草稿，不会自动发布内容。
- 当前项目主要用于演示 Agent 的工具调用、动态决策、状态管理和用户确认机制。
